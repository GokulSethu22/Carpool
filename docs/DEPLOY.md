# Carpool — Deployment Guide (Render Blueprint)

This guide walks through deploying the Carpool application to [Render](https://render.com) as a single Node.js web service using the included `render.yaml` blueprint.

---

## 1. Pushing to GitHub

Ensure your local project is committed and pushed to a GitHub repository:

```bash
# 1. Initialize git (if not already done)
git init

# 2. Stage all files (respecting .gitignore)
git add .

# 3. Create your initial commit
git commit -m "feat: complete Carpool production-ready application"

# 4. Set main branch
git branch -M main

# 5. Link your remote GitHub repository and push
git remote add origin https://github.com/<your-username>/carpool-tn.git
git push -u origin main
```

---

## 2. Creating the Service on Render from the Blueprint

1. Sign in to your [Render Dashboard](https://dashboard.render.com).
2. Click **New +** in the top navigation bar and select **Blueprint**.
3. Connect your GitHub account and select your `carpool-tn` repository.
4. Render will automatically detect the [`render.yaml`](../render.yaml) file in the root directory.
5. Click **Apply**. Render will:
   - Create a Web Service named `carpool`.
   - Set the runtime to `Node`.
   - Run the build command: `npm run build` (installs client & server deps, builds client into `client/dist`, compiles server into `server/dist`).
   - Run the start command: `npm start` (`node server/dist/index.js`).
   - Automatically configure health checks at `/api/health`.

---

## 3. Environment Variables

The blueprint automatically provisions all required environment variables:

| Variable | Description | Source / Default |
| :--- | :--- | :--- |
| `NODE_VERSION` | Explicit Node.js runtime version matching the local development environment (`v24.20.0`). | `24.20.0` |
| `NODE_ENV` | Sets runtime execution mode to production (enables static client serving, secure cookies, and trust proxy). Passed via start command to prevent devDependencies from being omitted during the build phase. | `production` |
| `JWT_SECRET` | Cryptographic secret for signing and validating session tokens. | Auto-generated by Render (`generateValue: true`) |
| `DB_PATH` | Path where the SQLite database file is stored. | `./data/carpool.db` |
| `PORT` | HTTP port assigned dynamically by Render (defaults to 10000 on Render). Express automatically binds to this port on `0.0.0.0`. | Injected by Render |

## 4. How to View Logs

- **Live Logs**:
  1. Open the [Render Dashboard](https://dashboard.render.com) and click on your `carpool` web service.
  2. Select the **Logs** tab from the left sidebar.
  3. You can inspect real-time server output, such as database startup messages, automatic seeding confirmation, and incoming HTTP requests.
- **Filter Logs**:
  - Use the search bar in the logs viewer to filter by keywords (e.g. `error`, `seed`, `health`).

---

## 5. What to Do if the Build Fails

If a deployment fails during the build or deploy phase:

1. **Check the Build Log**:
   - Go to the **Events** or **Logs** tab and inspect the red error trace.
2. **Node Version Incompatibility**:
   - Render defaults to its current standard Node release. Ensure `engines` in `package.json` matches (`>=24.20.0`). You can also specify an exact Node version in Render under **Environment** > `NODE_VERSION` (e.g. `24.2.0` or `20.18.0`).
3. **Missing or Failed Dependencies**:
   - Verify that `package.json` in root, `client/`, and `server/` have all required packages listed under `dependencies` rather than `devDependencies` if required at runtime.
4. **Clear Build Cache & Re-deploy**:
   - In the Render service page, click **Manual Deploy** in the top right and select **Clear build cache & deploy**.
